# MANGAI Cloud 100ページ長編・決定的受入れ v1

## 目的

長編制作機能が100ページ規模でも既存契約を維持することを、外部Provider、実利用者データ、本番DBに依存しない固定fixtureで継続検査します。

## Fixture

- 100ページ
- 10章、10話、20シーン
- 1シーン5ページ、1章10ページ
- 全ページに1コマと1枚の有効な画像素材
- 全ページを最新revisionで確定済み
- 一般向け作品のみ。Prompt、APIキー、Provider情報、利用者データは含めない

## 自動受入れ範囲

1. 章・話・シーン・ページの集約が100ページを欠損・重複なく扱う
2. コックピットの初期表示を24ページに制限する
3. 原稿preflightが100ページ、100コマ、100素材、全ページ確定を検査する
4. 制作進捗が100ページ完了として集約される
5. 固定版との差分が変更された10ページと余分な1ページだけを数える
6. 4ページ単位の25個のPDFを100ページの完成PDFへ結合する

実行コマンド:

```bash
npm run cloud:longform:acceptance
```

この検査は通常の`npm run hub:test`にも含まれ、退行時はCIを失敗させます。

## 保証しない範囲

- Supabase上の実データ100ページに対する所要時間とStorage容量
- 実画像を使った画質、ファイルサイズ、PDF目視品質
- 実ブラウザでのスクロール、メモリ、390px／768px／1280px表示
- Worker停止・再開、ネットワーク障害、Provider課金を含む実E2E
- チェックポイントからの実DB復元訓練

これらは外部環境を使うM6受入れとして別に実施します。固定fixture成功だけで本番100ページ対応完了とは判定しません。

## 変更境界

- migration追加なし
- 環境変数追加なし
- 外部API呼び出しなし
- 製品ロジック、認証、Storage、成人向け境界の変更なし
