# MANGAI Cloud コマ修正候補生成 v1

更新日: 2026-08-01

## 目的

一般向けCloud Canvasで、採用済みコマ画像の気になる部分を指定し、元画像と作品設定を参照した2〜4件の修正候補を生成する。

## 利用者フロー

1. 画像が配置済みのコマを選ぶ
2. 顔、手・指、表情、衣装、背景、全体仕上げから修正内容を選ぶ
3. 必要な場合だけ追加要望を入力する
4. 修正候補を2〜4案生成する
5. 候補を比較し、選んだ候補をコマへ配置する
6. 問題があれば、レイヤー表示またはUndoで元画像へ戻す

## 実装境界

v1は採用画像を先頭の参照画像として渡す、ガイド付きImage-to-Image候補生成である。画像内の指定範囲だけを置換するマスク付きInpaintingではない。Providerが参照画像入力に対応している場合に、構図と主要要素を保つ可能性を高めるが、変更範囲の完全な固定は保証しない。

## 維持する情報

- 採用済み画像Asset
- 対象コマのネーム
- Character Profileと利用version
- Style Bibleと利用version
- Location／Prop Profileと利用version
- 明示割当と参照画像
- Queue、quota、moderation、private Storage、所有者RLS

修正元Assetは、選択コマに表示中のレイヤーであり、同じ作品・同じ所有者に属することをサーバーで再確認する。署名URL、技術Prompt、内部エラーは利用者へ返さない。

## 非破壊編集

修正候補を採用すると新しいPanel layerとして最上部へ追加する。元レイヤーは削除しないため、表示切替、並べ替え、Undoで以前の状態へ戻せる。生成Job一覧には修正presetだけを公開し、非公開入力は返さない。

## 未対応

- ブラシで指定した範囲だけを置換するマスク付きInpainting
- Canvas外側を拡張するOutpainting
- ポーズ骨格やControlNetによる厳密な姿勢固定
- 修正前後の専用スライダー比較
- Providerごとの参照画像保持精度の実作品評価

## 受入れ条件

- 採用済み画像がないコマでは修正開始できない
- 別作品・別利用者のAssetを修正元にできない
- 修正元Assetが参照画像の先頭に固定される
- 修正後も人物・画風・世界設定のversionがJobへ保存される
- 元画像がレイヤーに残り、以前の状態へ戻せる
- 通常のコマ生成と失敗候補の再実行を壊さない
