# Cloud Research Corroboration Specification

## 入力

- 基準出典URL
- 比較出典URL
- 根拠分野

両URLは異なるHTTPS URLであること。認証、Research Feature Flag、Source Verification Feature Flag、allowlist、DNS検証、timeout、本文上限、rate limitは事実候補抽出と同じ契約を再利用する。

## 比較対象

各出典から分野別の事実候補を最大8件抽出し、候補間の組み合わせを比較する。

候補から次を決定的ルールで抽出する。

- 共通keyword
- 指標語（市場規模、売上、成長率、価格、単価、利用者、読者、販売数、シェア等）
- 数値
- 単位（%、円、万円、億円、人、件、冊、部、倍）
- 年

## 分類

### `corroborates`

共通分野keywordと共通指標語があり、同じ単位の同じ数値を含む。異なる年が明示されている場合は分類しない。

これは「同じ表現を持つ根拠候補」であり、事実が正しいことの保証ではない。

### `potential_conflict`

共通指標語、同じ単位、共通年があり、その単位の数値集合が一致しない。

同じ文に複数の数値がある場合や母集団が不明な場合があるため、「相反」と断定せず原文確認を必須にする。

### `related`

共通keywordまたは共通指標語はあるが、定量値、単位、年が比較条件を満たさない。

### `insufficient`

比較に必要な共通要素がない。UIの比較候補一覧には通常表示せず、比較可能な候補がない旨を表示する。

## 出力

最大6組。各組は次を持つ。

- relation
- 低または中のconfidence
- 判定理由
- 共通keyword、指標語、年
- 各出典の候補文と原文位置
- 各出典の検証metadata
- 出典domainが独立しているか

全文snapshotやraw bytesは返さない。

## UI

1. 検索候補を市場分析へ引き継ぐ
2. 比較出典URLを入力して照合を実行する
3. 両方の原文を開いて指標、時点、母集団、調査方法を確認する
4. 採用する組だけを出典1・2の事実欄へ転記する
5. 出典2の種別と公開日時を人が補完する
6. 市場分析を保存する

自動採用、自動保存、`potential_conflict`の自動棄却は行わない。

## Golden set

fixtureには最低限次を含める。

- 同年・同指標・同単位・同値
- 同年・同指標・同単位・異値
- 異なる年の異値
- 同値だが異なる指標
- 定量値を持たない関連文
- 無関係文
- 複数値を含む文

実Webや外部APIを使わず、期待分類と決定的な並び順を検証する。
