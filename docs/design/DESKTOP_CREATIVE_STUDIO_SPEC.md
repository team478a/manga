## 1. デザインコンセプト: MANGAI Creative Studio

### 1.1 参照する方向性と、それぞれから採用する具体的要素

| 参照 | 採用する要素 |
| --- | --- |
| Linear | 高密度な情報整理、左ナビの選択インジケータ（左2pxのaccentバー）、控えめな彩度、フラットな階層表現（影よりも背景の明度差で階層を作る） |
| Figma | 左右パネル＋中央Canvasのワークスペース構成、Canvas領域を暗くしてページ（成果物）を浮かび上がらせる、パネル内タブの使い方 |
| Raycast | Ctrl+Kコマンドパレット、検索駆動のナビゲーション、リスト行の高密度、キーボード最優先の操作性 |
| Adobe系制作ツール | 左＝構成・素材、右＝プロパティ・レイヤー、数値入力のペア配置（X/Y、W/H等）による高密度フォーム |
| 最新OS系UI（Windows 11 Mica/macOS Big Sur系） | 一時的に浮くUI（コマンドパレット、コンテキストメニュー、フローティングツールバー、トースト通知）だけに半透明+ぼかし（グラス表現）を限定使用。常設UI（パネル・ヘッダー・フッター）は不透明フラット面を維持 |

### 1.2 やらないこと（責任者指示の明文化）

- 常設パネル（左/中央/右/上部/下部）へのグラス表現の適用
- 過度なグラデーション、光沢、装飾的なアイコンセット
- 配色・CSS基盤（プレーンCSS＋CSS変数）の刷新（Tailwind化はしない）
- Desktopのダークテーマ・紫系アクセントからの逸脱

### 1.3 情報密度の設計思想

「初心者向け導線とプロ向けショートカットを両立する」ため、画面ごとに密度を使い分ける:

- **標準密度**（Home、設定画面の入力欄）: ラベル上・入力下の縦積み、行高32px前後。初めて触る利用者が迷わない余白。
- **高密度**（制作ワークスペースの右パネル、AI画像生成の詳細設定）: ラベル左・入力右または数値ペアの横並び、行高28px前後。Adobe系ツール利用者が数値を素早く追える密度。
- どちらの密度も同じトークン・同じコンポーネントAPIから導出し、`density: "standard" | "compact"` のようなprops差分として表現する（実装はPhase D1以降）。

## 2. 基盤トークン拡張案

既存24トークンは維持したうえで、以下を新規追加する（すべて案、コード未反映）。

### 2.1 階層（Elevation）

既存の3段階（`--bg-app` → `--bg-panel` → `--bg-panel-elevated`）を「常設UIの階層」として正式に採用し、影ではなく背景の明度差で階層を表現する既存方針を踏襲する。

| レベル | トークン | 値 | 用途 |
| --- | --- | --- | --- |
| 0 | `--bg-app`（既存） | `#101218` | アプリ全体の基底、左アイコンレール |
| 1 | `--bg-panel`（既存） | `#171a21` | 上部バー、左右パネル、下部ステータスバー |
| 2 | `--bg-panel-elevated`（既存） | `#1d212a` | パネル内のカード・リスト行（静止時） |
| 3（新規） | `--bg-raised` | `#242936`（＝既存`--bg-hover`と同値を再利用） | hover状態、または常時やや浮いたカード |
| 4（新規・グラス専用） | `--bg-glass` | `rgb(23 26 33 / 72%)`（`--bg-panel`をベースに透過） | コマンドパレット、コンテキストメニュー、フローティングツールバー、トースト、ドロップダウン、確認モーダルなど**一時的に出現するUIのみ** |

### 2.2 グラス表現の専用トークン（一時UI限定）

```css
--glass-bg: rgb(23 26 33 / 72%);
--glass-blur: 20px;
--glass-border: rgb(243 245 247 / 8%);
--glass-shadow: var(--shadow-dialog); /* 既存トークンを再利用 */
```

**適用可否の判定基準**: 「Escキーで閉じる／画面遷移せず一時的に出現する／背後のコンテンツが透けて見えることに意味がある」の3条件をすべて満たす場合のみグラスを使う。左右パネル、上部バー、下部ステータスバー、設定画面の本体、Canvas上の常設要素には**適用しない**（不透明な`--bg-panel`系を使う）。

`forced-colors`（Windows High Contrast）時は`backdrop-filter`が意味を持たないため、グラス要素は自動的に不透明な`--bg-panel` + `1px solid CanvasText`へフォールバックする（既存の`@media (forced-colors: active)`ルールを新規要素にも拡張する）。

### 2.3 アクセント拡張

既存の`--accent`/`--accent-hover`/`--accent-text`/`--accent-soft`に、押下状態を追加する。

```css
--accent-active: #5638c2; /* 既存 --accent を約12%暗くした値、ボタン押下時 */
```

`--accent-text`（`#9b86ff`）は「暗い背景の上に置く紫色の文字・アイコン」（リンク、アクティブなナビアイコン等）に用途を限定する。**accent塗りボタンの文字色は`--text-primary`（`#f3f5f7`）を使う**（`#6848d8`地に`#f3f5f7`はコントラスト比約5.48:1で、通常文字のWCAG AA基準4.5:1を満たす。`#9b86ff`より明確に読みやすいため）。

### 2.4 スペーシングスケール（新規・4pxグリッド）

```css
--space-1: 4px;   --space-2: 8px;   --space-3: 12px;  --space-4: 16px;
--space-5: 20px;  --space-6: 24px;  --space-8: 32px;  --space-10: 40px;
--space-12: 48px; --space-16: 64px;
```

### 2.5 タイプスケール（新規・既存実測値11〜19pxを正式な名前付きスケールへ整理）

```css
--text-2xs: 11px;  /* タイムスタンプ、微小ラベル、Page番号 */
--text-xs: 12px;   /* 補助テキスト、バッジ */
--text-sm: 13px;   /* 標準UI文字（ボタン、リスト行、フォーム） - 既存で最頻出 */
--text-base: 14px; /* 本文・説明文 */
--text-md: 15px;   /* 強調UI文字（コマンドパレット入力等） */
--text-lg: 18px;   /* パネル見出し */
--text-xl: 20px;   /* 画面見出し（Home等） */
--text-2xl: 24px;  /* Homeのメイン見出し */
line-height: 1.4（本文）/ 1.2（見出し）を既定とする。
```

### 2.6 角丸スケール（新規・既存実測4〜12pxを整理）

```css
--radius-xs: 4px;   /* チェックボックス、小タグ */
--radius-sm: 6px;   /* ボタン、入力欄、リスト行 - 既存で最頻出 */
--radius-md: 8px;   /* カード、パネル内セクション */
--radius-lg: 12px;  /* モーダル、コマンドパレット、ポップオーバー - 既存の一部モーダルで使用中 */
--radius-pill: 999px; /* ステータスpill、タグ - 既存で使用中 */
```

### 2.7 モーション（新規）

```css
--motion-fast: 120ms;
--motion-base: 180ms;
--motion-slow: 240ms;
--ease-standard: cubic-bezier(0.2, 0, 0, 1);
```

`prefers-reduced-motion: reduce`時は既存ルールを拡張し、コマンドパレットの出現アニメーション・生成中インジケータの脈動アニメーションもすべて`0ms`（即時表示・静止表示）にフォールバックする。

### 2.8 レイアウト定数

```css
--rail-width: 56px;       /* 左アイコンレール、全高さ共通・固定幅 */
--topbar-height: 48px;    /* 上部バー */
--statusbar-height: 28px; /* 下部ステータスバー */
```

## 3. 共通コンポーネント仕様

### 3.1 Button

| variant | 背景 | 文字色 | border |
| --- | --- | --- | --- |
| primary | `--accent`（hover: `--accent-hover`、押下: `--accent-active`） | `--text-primary` | なし |
| secondary | `--bg-panel-elevated`（hover: `--bg-raised`） | `--text-primary` | `1px solid --border-subtle` |
| ghost | 透明（hover: `--bg-hover`） | `--text-secondary` | なし |
| danger | `--danger` | `--text-primary` | なし |

サイズ: `sm`=28px高さ・`--text-xs`、`md`=32px高さ・`--text-sm`（既定）、`lg`=36px高さ・`--text-sm`。角丸`--radius-sm`。水平padding: `sm`=`--space-2`、`md`/`lg`=`--space-4`。フォーカス時は`--focus-ring`を適用。

### 3.2 Card

`variant="static"`（`--bg-panel-elevated`、hoverなし、設定画面カード等）、`variant="interactive"`（hoverで`--bg-raised`、クリック可能、Project一覧カード等）。角丸`--radius-md`、padding`--space-4`（標準密度）/`--space-3`（高密度）、`1px solid --border-subtle`。

### 3.3 StatusBadge（既存コンポーネントを正本として全画面へ拡張適用）

**tone（既存5種類、追加しない）**: `neutral` / `info` / `success` / `warning` / `danger`。この5種類のみを維持し、6種類目の`tone`は追加しない。

**activity（新規・独立したprop）**: 進行中の動作状態（生成中、確認中等）を表現するため、`tone`とは別の`activity`propを追加する。`activity="running"`のとき、既存の`tone`の色のドットが`--motion-slow`で不透明度70%↔100%を往復する脈動アニメーションになる（`reduced-motion`時は静止表示、色だけに依存しない）。`activity`未指定時は静的表示（既存動作のまま）。

```tsx
<StatusBadge tone="info" activity="running">生成中</StatusBadge>
```

ドット単体では使わず、必ず1〜3語のテキストラベルを併記する。

### 3.4 コマンドパレット（Ctrl+K）— 新規コンポーネント

**役割**: プロ向けの操作ハブ。ただしメニュー操作でも同じ機能へ到達できることを維持し、初心者には「存在を知らなくても困らない」設計とする。

**呼び出し**: `Ctrl+K`（全画面共通）。加えて上部バーに検索ボックス風のボタン（プレースホルダ「検索またはコマンド (Ctrl+K)」）を常設し、存在を可視化する（隠しコマンドにしない）。

**構造**:

- オーバーレイ: `rgb(0 0 0 / 50%)`のスクリム、クリックで閉じる
- パネル: `--bg-glass` + `backdrop-filter: blur(--glass-blur)` + `1px solid --glass-border` + `--glass-shadow`、角丸`--radius-lg`
- 幅: 640px（1920×1080）／520px（1366×768）、最大高さ60vh、内部スクロール
- 上部: 検索入力（`--text-md`、高さ44px、アイコン付き、placeholder「コマンドを入力…」）
- 結果リスト: セクション見出し（`--text-2xs`、`--text-muted`、大文字トラッキング）＋行（高さ36px、アイコン20px＋ラベル`--text-sm`＋右寄せショートカットヒント`--text-2xs`）
- セクション構成: 「最近」「移動」（Home／制作ワークスペース／AI画像生成／設定）「アクション」（新規Project、Undo/Redo、書き出し、コマ追加等 - 現在の画面文脈に応じて変化）「AI」（AI画像生成画面を開く、生成開始、**設定画面のAI Providerセクションを開く**）
- キーボード: ↑↓で移動、Enterで実行、Escで閉じる。フォーカスは開いた瞬間に検索入力へ、閉じたら呼び出し元へ復帰
- アクセシビリティ: `role="dialog"` `aria-modal="true"`、結果リストは`role="listbox"`/`role="option"`、`aria-live="polite"`で件数変化を通知

**安全境界（重要）**: コマンドパレットからProviderの有効/無効を即時切り替える項目は設けない。「AI」セクションの該当行は**設定画面のAI Providerセクションへ遷移するだけ**（§4.4のコマンドパレット連携と同じ「該当セクションを開く」動作）であり、その場でProviderを有効化・変更する操作は行わない。外部Provider（Dezgo等）の有効化、成人向け処理の切替、費用上限・外部送信の承認は、既存の確認フロー（設定画面での明示操作、費用見積り表示、同意ダイアログ等）を必ず経由し、コマンドパレットから迂回できない。

### 3.5 FormField

`density="standard"`: `<label>`（`--text-xs`、`--text-secondary`、`--space-1`下マージン）+ `<input>`（40px高さ、`--text-sm`）。`density="compact"`（プロパティパネル等）: ラベル`--text-2xs`＋入力28px高さ、2カラムのペア配置（X/Y、W/H等）は`display:grid; grid-template-columns:1fr 1fr; gap:--space-2`。エラー時は入力下に`--danger`で`--text-2xs`のメッセージ、入力枠を`1px solid --danger`。

### 3.6 フローティングツールバー（一時UI、グラス適用対象）

Canvas上・AI画像生成のプレビュー上に浮く操作列。`--bg-glass`＋blur、角丸`--radius-lg`、高さ40px、内部padding `--space-2`、ボタン間`--space-1`、グループ間に`1px solid --glass-border`の区切り線。常設ではなく対象領域にフォーカスがある時のみ表示する場合は`--motion-base`でフェード。

## 4. 画面仕様

各画面で「1920×1080」「1366×768」の2解像度、各領域の幅・余白・色・文字サイズ、主要操作、空状態、生成中状態、エラー状態、狭幅時の挙動を定義する。

**各領域**

| 領域 | 幅/高さ | 背景 | 内容 |
| --- | --- | --- | --- |
| 上部バー | 全幅 × 48px | `--bg-panel` | ロゴ+プロダクト名（`--text-sm`+`--text-2xs`のサブラベル）、コマンドパレットトリガー（幅320px、高さ32px、`--bg-panel-elevated`、`--radius-sm`）、言語切替、更新チャンネルバッジ |
| コンテンツ領域 | 最大幅1600px中央寄せ、左右余白は解像度により可変（下表参照） | `--bg-app` | 見出し・フィルタ・Projectグリッド |
| 下部ステータス帯 | 全幅 × 28px | `--bg-panel` | 自動バックアップ状態（`StatusBadge`）。左寄せ |

**Projectカード仕様**: `Card variant="interactive"`。代表画像はアスペクト比3:4、`--radius-sm`、カード上部70%を占める。画像下に作品名（`--text-sm` medium、1行省略+tooltip）、メタ行（`--text-2xs`、`--text-muted`、「第N話・更新からの相対時間」）。hoverで背景`--bg-raised`、右上にケバブメニュー（16pxアイコン、名称変更/複製/削除）が出現。カード全体がクリック可能（Enterキーでも開ける）。

**グリッド仕様（固定列数にしない）**: CSS Gridの`auto-fit`を使用し、列数は利用可能幅から自動的に決まる。**固定の列数・固定のカード幅は指定しない。**

```css
grid-template-columns: repeat(auto-fit, minmax(240px, 1fr));
gap: var(--space-4); /* 16px */
```

この設定では、コンテンツ領域の幅（=画面幅から左右余白を引いた値、最大1600px）に応じて列数が自然に変化し、カード幅は`240px`を下回らない範囲で残り幅を均等に伸縮する。目安として、以下の解像度でおおよそ次の列数になる（**設計上のガイド値であり、実装後は実測で確認する**）。

| 解像度 | 左右余白 | コンテンツ幅 | 結果として得られる列数の目安 |
| --- | --- | --- | --- |
| 1920×1080 | 64px | 1600px（上限で頭打ち） | 約5〜6列（カード幅は約240〜260px） |
| 1366×768 | 56px | 約1254px | 約3〜4列（カード幅は約240px前後） |

ウィンドウ幅がこれらの中間・それ以下の場合も、`auto-fit`により列数が同じ計算式で自然に減少する（固定ブレークポイントで列数を切り替えるのではなく、連続的に変化する）。

**主操作 / 副操作の優先順位**

## 5. ブレークポイント再編（提案・現行実装からの変更点）

現行実装（`styles.css`確認済み）は右パネルのoverlay化しきい値が1365pxであり、対象解像度の一つである1366×768が**境界のわずか1px上**という不安定な位置にある（[`UI_REDESIGN_PLAN.md`](UI_REDESIGN_PLAN.md)のPhase D0.5で指摘済みの既知リスク）。本仕様では、この問題を解消するため以下の5段階へ再編することを提案する。

| 段階 | 幅範囲 | 左パネル | 右パネル | 上部バー |
| --- | --- | --- | --- | --- |
| Spacious | ≥1920px | 280px | 320px | フルラベル |
| Standard | 1440–1919px | 260px | 300px | フルラベル |
| **Compact** | **1280–1439px（1366×768を含む）** | 240px | 260px | フルラベル維持 |
| Narrow | 1024–1279px | 220px | **overlay化**（グラス、Escで閉じる） | アイコンのみ |
| Minimal | <1024px | **overlay化** | overlay化 | アイコンのみ、breadcrumb省略 |

**現行実装との差分**: 右パネルoverlay化のしきい値を`1365px`→`1279px`へ引き下げる、ヘッダーのアイコン縮退しきい値を`1200px`→`1279px`付近へ統合する、`850px`の追加縮退は「Minimal」段階へ統合する。これによりCompact帯（1280〜1439px、1366×768を含む）ではパネルが狭まるがoverlay化しない安定した挙動になる。

**この表は値の変更を伴うため、Phase D0.5の「デザイン承認条件」と同様、実装着手前に責任者承認が必要な項目として扱う。**

## 6. 長い文字列・状態別の横断ルール

- **長いタイトル/ラベル全般**: 1行省略（`text-overflow: ellipsis`）+ `title`属性またはtooltipで全文。2行折返しは採用しない（カード高さ・行高の不揃いを防ぐ）。
- **空状態**: アイコン（装飾イラストは使わない、`--text-muted`の線アイコン20〜24px）+見出し+説明+主操作ボタン、という共通構成の`EmptyState`を全画面で統一使用。
- **エラー状態**: `role="alert"`、`--danger-soft`背景、アイコン+メッセージ+再試行/詳細ボタン。DB・API・Providerの生エラーメッセージは表示せず、既存のDomain Error契約の安全なメッセージのみ表示。
- **生成中状態**: `StatusBadge tone="info" activity="running"`（脈動する`--info`ドット+テキスト）を横断的に使用。Canvas編集・他操作をブロックしない。
- **blocked状態**（fail-closed判定）: 黙って無効化するのではなく、理由を`--warning-soft`のインラインパネルで明示し、解決導線（設定画面等へのリンク）を添える。

## 7. アクセシビリティ要件（横断）

`CURRENT_UI_AUDIT.md`§8.2に列挙した既存実装（skip link、`forced-colors`対応、`prefers-reduced-motion`対応、`Tabs.tsx`のARIA tablist、i18nキー整合、`localStorage`永続化キー、`data-a11y-*`フック）をすべて維持したうえで、新規要素に以下を適用する。

1. **コマンドパレット**: `role="dialog"` `aria-modal="true"`、`role="listbox"`/`role="option"`、開閉時のfocus trap・復帰、`aria-live="polite"`で結果件数を通知。マウスなしで開始から実行まで完結できること。
2. **グラス要素のコントラスト保証**: `--glass-bg`の不透明度は72%を下限とし、背後に何が表示されていてもテキストコントラスト比4.5:1（本文）/3:1（大文字）を確保する。`forced-colors`時はグラスを無効化し不透明`--bg-panel`+`1px solid CanvasText`へ自動フォールバック。
3. **フローティングツールバー**: `aria-label="キャンバスツールバー"`、Tabキーで到達可能、Canvas本体のアクセシビリティツリーを阻害しない。
4. **`activity="running"`の脈動インジケータ**: 色・アニメーションのみに依存せず、必ずテキストラベルを併記する。`prefers-reduced-motion`時は静止表示。
5. **2ペイン設定画面**: 左nav→右detailの読み上げ順序がDOM順序と一致すること。カテゴリ切替後、右detailの見出しへフォーカスまたは`aria-live`通知を行い、スクリーンリーダー利用者が切替に気づけるようにする。
6. **フォーカスリング**: 全新規インタラクティブ要素で既存`--focus-ring`を適用する。
